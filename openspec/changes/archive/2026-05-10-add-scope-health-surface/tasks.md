## 4. `verify_scope` tool

- [x] 4.1 Add `Server/Tools/Output/VerifyScopeResult.cs` — record type with `Scope`, `Status`, `StatusMessage`, `SchemaVersion`, `ViewsSchemaVersion`, `LastIndexedAt`, `RowCounts`, `IntegrityCheck`, `DriftSample`. `RowCounts` is the storage record; `DriftSample` is `(int sampled, int totalFiles, int changed, IReadOnlyList<string> changedPaths)` (cap `changedPaths` at 5 — the agent gets the count + a few examples).
- [x] 4.2 Add `VerifyScopeAsync` to `Server/Tools/ScopeTools.cs`. Args: `scope = "*"` (string). Iterates the resolved scope list; for each, opens the scope's `IGraphStore`, calls `RowCountsAsync` + `IntegrityCheckAsync`, samples 20 files via `SELECT path, content_sha256 FROM files ORDER BY RANDOM() LIMIT 20`, computes `SHA256(File.ReadAllBytes)` for each existing path, compares. Emits `notifications/progress` at three checkpoints (`"reading row counts"`, `"running integrity_check"`, `"sampling drift"`). _Order revised: integrity_check runs FIRST so a corrupt DB short-circuits before the row-count + sample queries (which would otherwise throw `SQLITE_CORRUPT` on btree pages). When integrity is non-`ok`, the response carries the integrity string and `null` for `row_counts` / `drift_sample` — matches the spec's "snapshot omits heavy fields when DB unhealthy" semantics. Sampling itself goes via the new `IGraphStore.SampleFileShasAsync(int limit)` helper; the SQL inline-in-tool would have been brittle._
- [x] 4.3 Wire into `Program.cs` tool registration alongside the other ScopeTools entries. Title prefix `🌿 verify_scope` per the existing leaf-brand convention; `Use when:` description "the agent suspects a scope is stale, corrupt, or empty and wants a structured snapshot before deciding whether to call repair tools". _Implicit: registration happens via `[McpServerToolType]` + `[McpServerTool]` attributes which `WithToolsFromAssembly()` (Program.cs line 317) discovers; the leaf brand is applied to every built-in tool by `ToolIdentityFormatter.ApplyBrandMark` (line 363). No explicit Program.cs edit needed._
- [x] 4.4 `VerifyScopeToolTests.cs` — happy path returns `Status = "ok"` with non-zero counts; degraded scope returns the persisted `StatusMessage`; drift sample with one file mutated on disk returns `changed = 1` and the path; integrity check on a corrupted DB returns the non-`"ok"` string. _4/4 pass._
