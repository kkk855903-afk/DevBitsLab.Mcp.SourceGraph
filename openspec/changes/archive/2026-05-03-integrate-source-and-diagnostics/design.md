## Context

Roslyn exposes generated documents via `Project.GetSourceGeneratedDocumentsAsync()`. Diagnostics come from `compilation.GetDiagnostics(cancellationToken)`. Both are deterministic and local to the document. The design choices are around storage shape and how to attribute diagnostics to the right symbol.

## Goals / Non-Goals

**Goals:**
- Generated documents are first-class but visibly distinct via the `is_generated` flag.
- Every Roslyn diagnostic with a non-empty location is captured, indexed for fast severity / code lookups.
- A diagnostic that targets a specific symbol resolves to that symbol's id; otherwise it's file-scoped.
- Live updates correctly invalidate diagnostics when the source file changes.

**Non-Goals:**
- Running custom analyzer packs not already loaded into the workspace. (Add via the extensibility mechanism if desired.)
- Capturing intermediate compiler warnings from out-of-band CLI builds. We rely on the workspace's own diagnostic stream.
- Diagnostic suppression decisions (suppression files, pragma comments). Deferred.

## Decisions

**1. Symbol attribution via location lookup.**
For each diagnostic, take its `Location.SourceSpan`, look up the smallest-enclosing declared symbol via the same syntax/semantic walk pass-1 already did. If found, set `symbol_id`; else `NULL` and the diagnostic is file-scoped only.

**2. Severity stored as int (`Hidden=0, Info=1, Warning=2, Error=3`).**
Matches Roslyn's enum integer values. Indexed for `WHERE severity >= ?` queries (an agent asking "show me the errors" filters with `>= 3`).

**3. Generated docs marked, not segregated.**
Rather than a separate `generated_files` table, we add `is_generated BOOLEAN` to `files`. Tools that don't care never see it; tools that should respect generation boundaries (e.g. `find_references` with default behaviour) filter out `is_generated = 1` unless the agent passes `include_generated = true`. This keeps the existing query layer intact.

## Risks / Trade-offs

- **Generated doc reindex churn.** A source generator can regenerate output on every keystroke; that's a stream of "changed" documents. Mitigated by hashing the generated text content (same SHA gate as regular files) so unchanged generated bytes don't reindex.
- **Diagnostic volume.** A noisy codebase can have thousands of warnings. Reconciliation per file (delete then re-emit) is fine at our scale; if it becomes a perf issue, batch into chunks.
- **Diagnostic without location.** Compiler errors like "missing reference assembly" have no source span. We skip them (not file-scoped, no symbol). Documented limitation; the relevant data is in MSBuild logs anyway.
